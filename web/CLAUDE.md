# web/ — Front Nuxt

Nuxt 4 (SSR) + `@nuxtjs/i18n` + `@nuxt/icon` + SCSS maison (voir `docs/adr/0008-choix-techniques-web.md`). Code applicatif sous `app/`, langues sous `i18n/locales/`.

## Règles
- **Jetons d'abord** : couleurs, ombres, espacements viennent de `app/assets/styles/_tokens.scss` (variables CSS). Jamais de valeur de couleur en dur dans un composant. Contour : `--border` (3 px d'encre, relevé des 2 px des maquettes qui paraissaient trop fins à l'écran) pour tous les cadres, champs, boutons et séparateurs : ne jamais écrire une épaisseur en dur.
- **Textes en clés** : aucun texte en dur dans les templates ; `t('section.clé')`. Le français est la référence (`fr.json`) ; les autres langues retombent dessus.
- **Erreurs d'API** : le front lit `code` et affiche `t('error.<CODE>')`, jamais `message`.
- **Énumérations** : codes anglais de l'API (`reading`, `plan_to_read`, `series`…), libellés dans les fichiers de langue.
- **Composants** : un sous-dossier de `app/components/` = un préfixe de nom (`ui/Button.vue` → `<UiButton>`). Réutiliser avant d'en créer ; la page `/components` les présente. Fichiers, routes et dossiers en anglais, textes affichés en clés i18n.
  - `ui/` génériques : `Button`, `Chip`, `Counter` (− / saisie / +), `EmptyState`, `Field`, `Modal`, `Panel` (bloc blanc à ombre), `Rule` (frise), `Tabs`.
  - `work/` œuvres : `Card` (fiche résumée : couverture, titre, type), `Cover` (avec/sans image, `small` ; sans image : trame rose vif `--color-rose-vivid` sur bleu pâle `--color-cover-blank`), et les blocs de la fiche : `Actions` (Lire/Acheter), `Info`, `People` (auteurs sur le web, repli au-delà de 3), `Rating` (note et membres), `Synopsis`, `Related`.
- **Fiche œuvre** : `pages/work/[slug].vue`, URL `/work/{id}-{slug}` (`/en/work/…`), un seul chemin pour toutes les langues (le préfixe change la langue). Seul l'`id` est lu ; slug erroné ⇒ 301 vers le canonique (calculé sur le titre affiché dans la langue de l'interface, comme les liens des œuvres liées) ; inconnue ⇒ 404. SEO : `useSeoMeta`, `useLocaleHead({ seo: true })` (canonical, hreflang), JSON-LD sérialisé par `serializeJsonLd`. Logique pure et types de la réponse dans `utils/work.ts`. Libellés des codes (`genre.*`, `workStatus.*`, `relationGroup.*`) en clés i18n ; un code absent s'affiche tel quel.
- **Galerie `/components`** : 404 en production (`NODE_ENV=production`), sauf `NUXT_PUBLIC_COMPONENT_GALLERY=true` (les E2E et docker-compose l'activent) ; indicateur unique `runtimeConfig.public.componentGallery`. La page d'accueil est `pages/home.vue` (`path: '/'`).
  - `layout/` structure du site : `Header`, `LanguageSwitcher` (bouton sur toute la carte + menu de liens `useSwitchLocalePath`, pas de `<select>` natif ; menu pleine largeur sous l'en-tête sur mobile, aligné à droite au bureau ; fermeture par Échap, clic extérieur ou changement de route).
  - `layout/ExploreMenu` (#97) : bouton « Explorer ▾ » de l'en-tête (☰ au mobile, fenêtre pleine largeur sous l'en-tête) listant formats et genres avec compteurs (`GET /works/facets`, chargé à la première ouverture, ordre éditorial `pickExploreFacets`) et « Voir tout le catalogue ». `v-model:open` : `Header` le referme à l'ouverture de la recherche (jamais deux croix). Absent de `/search`.
- **Layouts** (`app/layouts/`) : convention Nuxt, ce sont les coquilles qui entourent les pages. `default.vue` s'applique à toutes les pages (lien d'évitement, en-tête, zone de contenu `<slot />` qui s'étire sur toute la hauteur de la fenêtre : le contour de focus de `<main>` entoure toute la page) ; un autre layout (ex. connexion sans en-tête) se choisit par page avec `definePageMeta({ layout })`.
- **Tests** : colocalisés avec le code (`foo.ts` + `foo.spec.ts`), comme `hortibat_frontend`. Vitest (environnement Nuxt, `mountSuspended`) : tout fichier `.vue` (composant, page, layout, `app.vue`, `error.vue`) a son `.spec.ts` voisin ; la logique pure vit dans `utils/` (testée sans Nuxt) et `composables/` ne fait que la brancher sur Nuxt. Seuil de couverture : 80 % (lignes, instructions, fonctions, branches), analyse Sonar de `web/` (projet `VerlandeRyan_Trame_web`, `sonar-project.properties`). Les parcours sont dans les E2E, avec un contrôle automatique d'accessibilité axe-core (WCAG 2 A/AA) sur chaque page. Le cache disque de Vitest (`fsModuleCache`) est désactivé : avec l'environnement Nuxt il fait échouer les exécutions suivantes. Ne pas utiliser `mockNuxtImport` (casse la résolution des imports de l'environnement Nuxt sous Windows) : injecter les dépendances, comme `createApiClient`.
- **Trame** : mixin `screentone` (`app/assets/styles/_mixins.scss`).
- **Appels API** : `useApi().request()` (erreurs normalisées par `toApiError`), message affiché via `messageKeyFor(error)` ; logique pure dans `app/utils/api-error.ts` (testée). Le SSR appelle l'API directement (`NUXT_API_BASE`) ; le navigateur appelle `/api/v1/…` sur le même site, relayé par `server/api/v1/[...path].ts` (GET seulement pour l'instant).
- **Recherche** (#21, maquettes 03/04, US-01) : `layout/SearchBox` (combobox ARIA : suggestions dès 2 caractères après 200 ms, 3 lignes + « Voir les N résultats », flèches/Entrée/Échap, clic extérieur ; une erreur d'API ferme le menu sans message) dans l'en-tête, la 404 et la page `/search`. Au mobile, l'en-tête n'affiche qu'une icône qui **déploie le champ dans l'en-tête** (logo, langue et compte s'effacent, croix pour fermer, Échap ou changement de page aussi) : la page courante reste dessous et le menu s'y pose ; l'icône est masquée sur `/search`, qui porte son propre champ. `pages/search.vue` : l'**URL est la source de vérité** (`q`, `type`, `format`, `genre`, `status`, `originalLanguage`, `page`) ; valeurs invalides ignorées (`parseSearchQuery`), **plusieurs valeurs par groupe** (liste séparée par des virgules dans l'URL ; OU dans un groupe sauf les genres en ET, ET entre groupes), changer un filtre revient à la page 1. Deux appels : `GET /works` (liste) et `GET /works/facets` (compteurs, hors `lang` et `page`). `search/Filters` (état ouvert/fermé par groupe, lien « Tout replier / Tout déplier ») + `search/FilterGroup` (bouton à chevron à gauche, pastille du nombre de choix, groupe masqué s'il n'a aucune valeur ; Type, Format, Genre dépliés), feuille basse `UiModal placement="bottom"` au mobile (maquette 04 : pied « Réinitialiser » + « Voir N résultats », `Filters sheet`), `ui/Pagination` par liens, `search/ResultItem`. Tri par `ui/Select` (menu stylé, texte « Trier par Pertinence ▾ » ; `relevance`, `title`, `recent`) : `sort` dans l'URL seulement s'il diffère de la pertinence, envoyé à la liste mais jamais aux compteurs ; le menu de suggestions se rouvre au clic ou au focus du champ. Page en `noindex`. Le bouton « Ajouter » (#23) et « Proposer cette œuvre » (US-09) sont visibles mais inactifs. Logique pure dans `utils/search.ts`.
- **Accueil** (#79, maquettes 05/06, US-15) : `pages/home.vue` charge en parallèle `GET /works/featured`, `/works?sort=recent&pageSize=12` et `/works/top-rated` ; **un bloc vide ou dont l'appel échoue est masqué** (`optional()`), jamais d'erreur affichée. **Hero visiteur** (#95, accueil v2) : bande sur fond bleu pâle `--color-field-soft` (seule bande teintée, le reste reste sur le papier) ; à gauche titre en Poppins 800 (`--font-display`, `@fontsource/poppins/latin-800.css`, auto-hébergée), tampons de formats inclinés (décor `aria-hidden`, une seule ligne jusqu'à 320 px : corps `min(0.78rem, 2.9vw)`), sous-titre à mots clés surlignés (`i18n-t`, `<mark>`), recherche ; à droite `home/Pitch` (« Pourquoi Trame ? » : 3 engagements, bouton « Créer ma liste de lecture » inactif jusqu'à #22 ; sous la recherche au mobile). Le panneau n'est pas encore conditionné à la session (#22) ; un membre connecté ne le verra pas (#96). Icônes du panneau aux couleurs de l'app : vert « En cours » (suivi), lavande « À lire » (tout au même endroit), jaune de « À la une » (découverte). Jetons `--color-yellow`, `--color-cyan`, `--color-crimson` (contrastes dans `contrast.spec.ts`). **Le bloc Explorer n'est plus sur l'accueil** : il est dans l'en-tête (`layout/ExploreMenu`, #97) ; `home/Explore` reste dans la galerie `/components`. Blocs : `home/Featured` (carrousel sans défilement automatique : précédent/suivant, pastilles ; badge jaune doré), `home/Shelf` (rangée sur une seule ligne : 12 œuvres demandées, autant affichées que la largeur le permet, chacune d'au moins 136 px / 104 px au mobile, qui se partagent toute la largeur ; « Tout voir » facultatif, absent pour « Mieux notées » faute de tri par note), « Une œuvre manque » (bouton inactif, US-09). L'accueil porte son propre champ de recherche (`LayoutSearchBox` + bouton « Rechercher » au bureau) : **l'en-tête n'en a pas sur `/`** (`layout-header--plain`). Bloc connecté « Ma liste de lecture » : avec la connexion (#22). Logique pure et types dans `utils/home.ts`. Dimensions relevées dans le HTML des maquettes 05/06 (bande « hero » pleine largeur fermée par un filet ; blocs séparés de 26 px ; rangées d'œuvres de 136 px au moins (104 px au mobile) étirées sur toute la largeur, une seule ligne, les œuvres qui ne tiennent pas sont masquées ; ordre éditorial des formats et genres dans `exploreCodes`). Écarts assumés : cadres de `--border` (3 px) au lieu de 2 px ; boutons à 44 px (`UiButton`, comme le reste du site) ; pastilles d'Explorer, flèches et pastilles du carrousel à la taille de la maquette avec une **zone tactile de 44 px invisible** (`::after`). Les marges de `<main>` sont des variables (`--main-pad-*`) que l'accueil annule pour ses bandes. **Animations** (toutes dans `@media (prefers-reduced-motion: no-preference)`) : le carrousel passe par un `<Transition mode="out-in">` dont le sens (variable `--slide-shift`, ±24 px) suit le clic (suivant, précédent, pastille) ; rien n'apparaît en fondu à l'arrivée sur la page (cela fausserait le contraste mesuré par axe-core). Pas de défilement automatique, mais le carrousel se **fait glisser au doigt** (`pointerdown`/`pointerup` de `featured__stage`, `touch-action: pan-y`, `swipeStep` dans `utils/home.ts` : seuil de 40 px, geste plutôt horizontal ; la souris est ignorée). Au doigt, flèches, pastilles et chips prennent leur couleur de survol à l'appui (`:active`). Les chips d'Explorer penchent de 1,2° (les boutons de 2,5° : une pastille large dévie plus pour un même angle) et s'étirent pour que chaque rangée occupe toute la largeur.
- **Survol** (système unique, validé sur maquette interactive) : **souris seulement**, via les mixins `on-hover` (`@media (hover: hover) and (pointer: fine)`, jamais sur un élément désactivé) et `tilt-on-hover` de `_mixins.scss` ; sur écran tactile seul `:active` répond (sinon `:hover` reste collé après un toucher). Deux mouvements seulement : l'**inclinaison** « autocollant » (`rotate(-2.5deg) scale(1.05–1.06)`, rebond) pour les boutons (`UiButton`, « Voir la fiche ») et les pastilles, et le **soulèvement** de 3 px des couvertures ; flèches du carrousel : rose franc + montée d'1 px ; pastilles du carrousel : rose franc sauf la sélectionnée. Couleurs : boutons vers `--color-rose-strong` / `--color-blue-strong` / `--color-cover-empty` ; formats `--color-rose` ; genres `--color-rose-soft` ; « Tous les… » `--color-cover-empty`. `utils/contrast.spec.ts` lit `_tokens.scss` et garde ces fonds au seuil AA avec le texte d'encre (`rose-strong` est le rose le plus foncé qui passe : 4,55:1). Tout survol, y compris sur les composants plus anciens (`LanguageSwitcher`, `ResultItem`), suit cette règle.
- **Zones de clic** : une zone tactile invisible de 44 px (`::after`, ou un bouton de 32 × 44 px pour les pastilles du carrousel) **ne doit jamais en recouvrir une autre** : la dernière dans le DOM capte le clic de sa voisine. Écarts qui en découlent : 14 px entre les flèches, boutons de pastilles côte à côte, 16 px entre les pastilles d'Explorer. **La zone dépend de l'appareil** : à la souris (`pointer: fine`) elle épouse l'élément (pastille de carrousel : 32 × 28 px, flèche : ses 30 px, pastille d'Explorer : son cadre) pour que le curseur n'active pas un bouton situé à côté ; au doigt (`pointer: coarse`) elle monte à 44 px. Le test E2E `elementFromPoint` de l'accueil le contrôle à 1280 et 390 px. Boutons inactifs (`UiButton disabled`) : opacité 0,5, ombre conservée, curseur d'interdiction. « Tout voir » passe au bleu `--color-blue-light` au survol.
- **Page 404** (`app/error.vue`, maquettes 24/25) : grand « 404 », titre, même texte d'aide au bureau et au mobile, champ de recherche (`LayoutSearchBox`), bouton « Retour à l'accueil ». Les autres erreurs gardent `UiEmptyState`. La « fiche archivée » (maquette 24, état 6) attend un code d'erreur API dédié.
- **Trame du bord droit** : sur l'accueil (`definePageMeta({ trame: 'hero' })`), elle vit seulement dans la bande du hero (`.home__hero::before`, même motif, coupée au filet, opacité 0,4 : il n'y a pas de texte courant dessous) ; partout ailleurs `layouts/default.vue` pose une colonne de points roses (`--color-trame-side` = `--color-rose-vivid`, comme les couvertures sans image ;  24 % de la largeur au mobile, 30 % dès 768 px), `position: fixed` derrière `<main>` (`z-index` 0/1), qui s'estompe vers la gauche et vers le bas. Décor pur : `aria-hidden`, `pointer-events: none`, opacité 0,23 (à 0,4 les points gênaient la lecture du tri et des titres) ; `e2e/tests/layout.spec.ts` vérifie qu'elle est présente, au bord droit et qu'elle ne capte aucun clic. Les marges de `<main>` annulées par l'accueil ne la concernent pas.
- **Listes** : `ul`/`ol` sans puces ni retrait par défaut (`main.scss`).
- **Animations** : toute transition ou animation se déclare dans `@media (prefers-reduced-motion: no-preference)`, jamais de `!important` ni de règle globale « reduce » (Sonar le signale).
- **Pas de pied de page** tant qu'il n'est pas maquetté ; à définir en temps voulu (mentions légales : #35).
- **Lisibilité** : noms explicites (pas d'abréviations d'une lettre), classes BEM par composant (`counter__button`), pas de ternaires imbriqués, un fichier = une responsabilité.
- **Contraste AA** (mesuré le 2026-10-14) : encre `#1b2a5c` sur les cinq couleurs de statut ≥ 4,59:1, sur le rose 5,20:1 ; blanc sur bleu 8,41:1. Ne jamais mettre de texte blanc sur une couleur de statut (1,45 à 2,98:1).
- **Icônes** : `<Icon name="tabler:…" />` uniquement ; aucune police d'icônes ni CDN.
- **Appareils** : zones tactiles ≥ 44 px (`--touch`), champs à 16 px minimum (Safari iOS), pas de défilement horizontal, `100dvh` plutôt que `100vh` seul. Points de rupture : 768 et 1024 px.
- Pas de `v-html` sur du contenu utilisateur ; données de démo fictives uniquement.
- URL : français sans préfixe, autres langues en `/en/…` ; liens via `useLocalePath()`.

## Commandes
- `npm run dev` : serveur de développement (API attendue sur `NUXT_API_BASE`, `http://localhost:3000` par défaut).
- `npm run typecheck` (`vue-tsc`), `npm run lint` (ESLint, règles renforcées comme `hortibat_frontend`), `npm run format` / `format:check` (Prettier : sans point-virgule, guillemets simples, 100 colonnes), `npm test` / `npm run test:coverage` (Vitest, logique pure, couverture lcov), `npm run build` puis `npm run preview`.
- E2E : `e2e/` ; construire `web/` d'abord, puis `npm test` dans `e2e/` (localement, `npm run test:desktop` suffit ; la CI exécute aussi WebKit iPhone). Les E2E lisent la **vraie API** (`api/dist/server.js`, donc `npm run build` dans `api/` aussi) sur la base de test (`TEST_DATABASE_URL`, migrée par `npm run migrate:test`) : `e2e/support/global-setup.ts` y recharge `db/demo-data.sql` avant chaque exécution. Les parcours s'écrivent donc sur les données de démo (ex. `q=basalte`, fiche `/work/1-les-lanternes-de-brume`) ; changer le jeu de démo peut casser un E2E comme un test de l'API. Il n'y a plus de doublure d'API.
- TypeScript 6 ici (vue-tsc et typescript-eslint ne gèrent pas encore TypeScript 7, utilisé par `api/`).
